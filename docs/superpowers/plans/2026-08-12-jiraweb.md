# JiraWeb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Standalone local web tool replacing Mission Control's WPF Jira workspace at full parity — React+Vite+TS SPA served by an Express+TS server that proxies Jira REST, owns SQLite caches, and runs the Lumo AI CLI agent.

**Architecture:** `server/` (Express, better-sqlite3, config in `%APPDATA%\JiraWeb`) exposes `/api/*` consumed by `client/` (React SPA). PAT never reaches the browser. Client mirrors WPF views 1:1; server mirrors WPF Infrastructure/Application layers 1:1.

**Tech Stack:** Node 20+, Express 4, better-sqlite3, tsx, vitest; React 18, Vite 6, TypeScript 5. Charts: build per `dataviz` skill; drag-drop: native HTML5 DnD.

## Global Constraints

- **Authoritative behavior specs live in `docs/reference/`:** `jira-rest-layer.md` (endpoints, mapper, JQL, caching, orchestration), `storage-layer.md` (SQLite schema, repos, AppSettings, file stores), `ui-parity-contract.md` (per-view UX). Every task MUST read its named sections before coding. Where this plan and a reference doc disagree, the reference doc wins.
- Server binds `127.0.0.1` only. Default port 5643.
- Data dir: `%APPDATA%\JiraWeb\` — `config.json` (credentials+profile), `jiraweb.db` (SQLite), `create-defaults.json`, `create-meta-cache.json`.
- Instance type default **DataCenter** (Bearer PAT); Cloud (Basic email:token, `rest/api/3`, ADF comment bodies) must work too.
- JSON over the wire between client/server: camelCase. SQLite JSON blob columns: PascalCase (storage-layer.md §8.1) — fresh DB, but keep convention for potential import of existing `command-center.db`.
- All Jira default project fallback: `"ISW"`.
- Tests: `npm run test --workspace server` / `--workspace client` (vitest). Commit after every task.
- Commit messages end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

**Routes (all under `/api`):**

- `GET /boards` (+`?force=1` clears cache key first); `GET /boards/:id/sprints|issues|quickfilters`.
- `GET /dashboard/snapshot`; `GET /timelogged?period=&from=&to=&user=` (+`/sprint?name=`, `/range?from=&to=`).
- `POST /incidents/search` {selections, summarySearch} → {all, verification, rejected} (3 parallel).
- `GET /incidents/filter-options/:filterId` (resolution rules per ui-parity §3).
- `GET/PUT /settings` (AppSettings whole-object, load-then-mutate on PUT); `POST /settings/clear-issue-cache`; `POST /settings/hard-refresh` (issue+meta+createmeta clear + reset field cache).
- `GET/POST/DELETE /filters` (saved filters); `GET/POST/DELETE /teams`; `GET/POST/DELETE /pinned-boards`.
- `GET /create/meta?project=&type=` (file cache, 14d, 15s timeout → error json), `POST /create/issue`, `GET/PUT/DELETE /create/defaults?key=`.
- `GET /metadata/:kind` (projects|issuetypes|statuses|priorities|resolutions), `GET /metadata/users?project=`, `/versions`, `/components`, `GET /metadata/distinct?project=&field=&max=`, `GET /metadata/suggestions?field=&query=`.
- `GET /misc/attachment-proxy?url=` — only URLs on the Jira base host; injects auth header; streams response.
- 401 from Jira anywhere → respond 401 (client redirects to login). Error shape `{status, message}`.
- `main.ts`: express.json, routes, static-serve `client/dist` + SPA fallback, listen 127.0.0.1:5643, auto-activate session from saved config on boot (ping /myself; failure leaves disconnected).
